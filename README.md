# vieillitude — Friend Portraits

A static website sharing 25 years of yearly portraits of a group of friends. Two interactive views: scrollable grid (matrix) and per-friend timelapse.

**Hosted on:** GitHub Pages  
**Built with:** Node.js (build script), vanilla HTML/CSS/JS (frontend)  
**Images:** Git LFS  
**Access:** Passphrase gate + `robots.txt` (Option A — see [ACCESS-PROTECTION.md](docs/ACCESS-PROTECTION.md))

---

## Quick Start

### Local Development

```bash
# Install dependencies
npm install

# Generate placeholder test photos (one-time, for testing)
npm run setup

# Build: walk photos/, generate WebPs, emit manifest
npm run build

# Serve locally
cd site
python3 -m http.server 8000
# Visit http://localhost:8000
# Passphrase: friends2026
```

### Publishing a New Year

1. Add new photos to `photos/<friend-slug>/<year>.*` (e.g., `photos/alice/2025.jpg`)
2. Commit and push
3. GitHub Action runs automatically, rebuilds site, deploys to Pages

```bash
# Or test locally before pushing
npm run build
# Site is updated in site/
```

## Build Process

The build script (`build/scripts/build.js`):

1. **Walks** `photos/<slug>/<year>.*` (all extensions supported: .jpg, .png, etc.)
2. **Generates** two WebP sizes per photo:
   - `<year>-thumb.webp` (300px, 80% quality) — for matrix grid
   - `<year>-full.webp` (800px, 90% quality) — for timelapse view
3. **Outputs** to `build/dist/<slug>/` and copies to `site/photos/`
4. **Emits** `manifest.json` reflecting exactly what's on disk (no manual edits)

**Missing years** are gracefully handled:
- If a friend is missing a year, that year's cell renders as `—` in matrix
- Timelapse slider only includes available years (no blank frames)

### Usage

```bash
npm run build              # Full build
npm run setup              # Generate placeholder test images
```

### Manifest Structure

```json
{
  "friends": [
    {
      "slug": "alice",
      "displayName": "Alice",
      "years": {
        "2001": "photos/alice/2001-thumb.webp",
        "2002": "photos/alice/2002-thumb.webp"
        // Missing years simply don't appear here
      }
    }
  ],
  "yearRange": { "min": 2001, "max": 2026 }
}
```

## Frontend

### Matrix View (`index.html`)

- **CSS Grid** with sticky header (years) and sticky left column (friend names)
- Scrollable in both directions for large grids
- **Real-time text filter** by friend name (client-side, no server)
- Empty cells for missing years render as subtle `—` placeholder
- **Timelapse button** per friend navigates to timelapse view
- Passphrase gated (Option A)

**Navigate:**
- Scroll both directions for friend × year grid
- Type in filter box to hide/show rows
- Click "Timelapse" button on any friend

### Timelapse View (`timelapse.html?slug=<slug>`)

- **Per-friend fullscreen view** — displays large photo + year label
- **Slider** to navigate through available years only (gracefully skips gaps)
- **Play/Pause button** — auto-cycles at 1 second per frame, loops
- **Keyboard controls:**
  - ← → arrow keys to step through years
  - Space to play/pause
- Back button returns to matrix (session preserved)
- Fetches full-size WebPs (not thumbnails)
- Passphrase gated (Option A)

**Navigate:**
- Move slider or use arrow keys to browse years
- Press Play or Space to auto-cycle
- Click Back to return to matrix

## Access Protection

**Option A** (current) — Obscurity + light gate:
- Random URL (handled by GitHub Pages)
- `robots.txt` blocks all search engines
- `<meta name="robots" content="noindex">` on all views
- Client-side passphrase prompt before viewing
- **Not real security** — determined visitors can view source and bypass
- **Good for:** keeping off search engines, casual discovery prevention

**Passphrase:** `friends2026` (change in `site/js/gate.js` before deploying)

**To swap to Option B** (Cloudflare Access):
- Remove `site/js/gate.js`
- Remove gate DOM and imports from both HTML files
- Configure Cloudflare Access with email whitelist
- No changes needed to matrix/timelapse code

See [ACCESS-PROTECTION.md](docs/ACCESS-PROTECTION.md) for details.

## Deployment

### GitHub Pages (Automatic)

1. Ensure repo is public (or Pages is enabled on Pro account)
2. Go to **Settings** → **Pages** → **Build and deployment**
3. Set source to **GitHub Actions**
4. On push to `main`, the workflow runs:
   - Installs dependencies
   - Runs `npm run build`
   - Deploys `site/` to GitHub Pages
5. Site is live at `https://<username>.github.io/vieillitude/`

### Custom Domain

Edit `.github/workflows/build-and-deploy.yml`, line 34:
```yaml
cname: your-domain.com
```
Then configure DNS and GitHub Pages settings accordingly.

### Local Testing

```bash
cd site && python3 -m http.server 8000
# http://localhost:8000
```

## Source Images & Git LFS

### Adding Photos

1. Create friend directory (if new):
   ```bash
   mkdir -p photos/jean-dupont
   ```

2. Add image file:
   ```bash
   cp ~/Pictures/jean-2025.jpg photos/jean-dupont/2025.jpg
   ```

3. File must be named `<year>.<ext>` (e.g., `2001.jpg`, `2024.png`)

4. Commit and push:
   ```bash
   git add photos/
   git commit -m "Add 2025 photos"
   git push
   ```

### Git LFS Setup

`.gitattributes` configures LFS to track all image files in `photos/`:
```
photos/**/*.jpg filter=lfs diff=lfs merge=lfs -text
photos/**/*.png filter=lfs diff=lfs merge=lfs -text
# ... etc
```

**Do NOT commit generated files:**
- `build/dist/` — temporary build artifacts
- `site/photos/` — generated WebPs
- `site/manifest.json` — generated by build

These are in `.gitignore` and will be regenerated on every build.

### Install Git LFS

```bash
# macOS
brew install git-lfs
git lfs install

# Ubuntu/Debian
sudo apt-get install git-lfs
git lfs install

# Windows
# Download from https://git-lfs.com/
```

2. Create folder: `mkdir photos/<slug>`
3. Add images: `photos/<slug>/<year>.*`

- Lowercase, hyphenated
- Decoupled from display name (renames won't break history)

## Troubleshooting

### Images show as broken in matrix

- Run `npm run build` to regenerate WebPs
- Ensure `site/photos/` exists and contains WebP files
- Check browser console for 404 errors (File > Developer Tools > Console)

### Timelapse shows "Error: No friend slug provided"

- URL should be `timelapse.html?slug=alice` (with query param)
- Ensure slug matches a friend folder in `photos/`

### Passphrase gate always prompts

- Session storage may be cleared (private/incognito mode)
- Change browser or use normal browsing mode
- Passphrase is cached per browser session (`sessionStorage`)

### Build script errors

```bash
npm install         # Reinstall dependencies
npm run build       # Retry build
```
